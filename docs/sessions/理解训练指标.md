**CSV 格式**（无表头，每行 = 一个口技单音）：

## 一、你问的四个词

**1. step（步）** —— 模型每看完一批数据、做一次"反向传播+参数更新"，就走了一步。我们这次共 **3,064 步**。它是训练进度的最小计数单位，日志里 `global_step/max_steps: 410/3064` 就是"当前第 410 步 / 总共 3064 步"。

**2. epoch（轮/纪元）** —— 把整个训练集**完整过一遍** = 1 个 epoch。我们的算法是：

```
epoch = step ÷ (训练集样本数 ÷ 有效batch大小)
      = step ÷ (12256 ÷ 8) = step ÷ 1532
```

所以 `epoch: 1.00` 正好出现在 step 1532 附近——**第一遍数据读完了**；我们设了 `num_train_epochs=2`，所以总共 3,064 步 = 2 遍。epoch 是"按数据量"的进度，step 是"按更新次数"的进度，两者一一对应。

**3. eval_loss 和 eval_token_acc** —— 训练每隔 500 步**暂停一次**，拿 1,530 条**模型从没见过的验证集**数据测一遍：

- **eval_loss（验证损失）**：衡量"模型预测错得多离谱"的分数。每个位置模型都会给正确答案一个概率，loss 就是 **-log(正确答案的概率)**。比如模型给正确答案 92% 的概率 → loss = -log(0.92) ≈ 0.083；只给 50% → loss = 0.69。**越低越好，0 = 完美**。它和训练 loss 的核心区别：**训练 loss 有"背答案"成分，eval_loss 代表真本事**。
- **eval_token_acc（验证 token 准确率）**：逐个 token 统计"模型猜中的比例"。我们的任务里正确答案（如"这段音频模仿的是**军鼓**…"）基本是固定句式，所以这个数天然就高（96%+），**看它的变化趋势比看绝对值有意义**。

**4. TrainOutput** —— 训练**结束时** HuggingFace Trainer 打印的最终汇总对象，不是过程指标。训练跑完你会在日志末尾看到：

```python
TrainOutput(global_step=3064, training_loss=0.075,
  metrics={'train_runtime': 21600, 'train_samples_per_second': 1.13, ...})
```

它回答三个问题：**跑了多久**（train_runtime 秒）、**平均速度**（每秒几个样本/几步）、**全程平均 loss**。训练中途是看不到它的。

## 二、每次打点那一行日志的逐字段拆解

以我们真实的一条为例：

```python
{'loss': '0.08311',          # 训练 loss：最近 logging_steps=5 步的平均值
 'grad_norm': '0.1663',      # 梯度范数：权重更新幅度的"体检值"（见下）
 'learning_rate': '7.11e-05',# 当前学习率（cosine 退火，从 1e-4 逐渐降到 0）
 'token_acc': '0.968',       # 训练集上的 token 准确率
 'epoch': '0.7866',          # 轮次进度
 'global_step/max_steps': '1205/3064',
 'elapsed_time': '3h 27m',   # 已用时
 'remaining_time': '1h 59m', # 预计剩余
 'memory(GiB)': '6.55',      # 显存占用
 'train_speed(s/it)': '10.3' # 每步耗时（秒）
}
```

**grad_norm（梯度范数）**：所有参数梯度合成一个向量的长度。它是**数值稳定性的警报器**——正常值 0.1~1 之间平稳波动；**突然飙到几百上千或变成 NaN，说明梯度爆炸、训练要崩**，这时看 `logging_nan_inf_filter` 是否滤掉了异常步。我们全程 0.07~0.4，非常健康。

**learning_rate（学习率，lr）**：每次更新参数的"步长"，是**对训练影响最大的超参**。太大学习会震荡发散（loss 上蹿下跳），太小学不动。我们用的调度策略：

| 概念 | 作用 | 我们的取值 |
|---|---|---|
| warmup（预热） | 前几步 lr 从 0 线性升到峰值，避免开局乱跳 | 前 5% 步数 |
| cosine（余弦退火） | 之后 lr 沿余弦曲线平滑降到 0——前期大步学、后期小步精修 | 1e-4 → ~0 |

到 step 2850 时 lr 已降到 4.5e-07，这解释了后期 loss 下降变缓：**收尾阶段本来就是微调**。

**memory(GiB) / train_speed**：运维指标。显存 6.55→8.1GB（eval 时更高），说明 4bit QLoRA 只占 24GB 卡的三分之一；8-10s/it 可反推总时长。

## 三、判断训练健康的核心方法：train loss vs eval loss

三个信号组合起来看（对照上图）：

| 现象 | 含义 | 我们的情况 |
|---|---|---|
| train ↓ 且 eval ↓ | 正常学习 | step 500→1000 ✅ |
| train ↓ 但 eval ↑ | **过拟合**（背题了，泛化变差） | step 1000 后 ⚠️ epoch 2 出现 |
| train 与 eval 都平 | 到达能力平台 | epoch 1 后期 token_acc 停在 96.5% |
| loss 突然尖峰 / NaN | 数值不稳定，需降 lr | 无 ✅ |

我们这次的标准剧本：**最佳点在 step 1000（eval_loss 0.08856）**，之后 epoch 2 轻微过拟合。所以最终产物取 step 1000 的 checkpoint——这就是 `metric_for_best_model=loss` + `load_best_model_at_end` 的作用：**Trainer 自动记住 eval_loss 最低的那次，保存并最终回载它**，而不是傻傻用最后一步。

另外两个保存相关概念：**checkpoint**（每 500 步存一次的"存档"，含 LoRA 权重+优化器状态，可断点续训 `resume_from_checkpoint`）；**save_total_limit=3**（最多只留 3 份，防磁盘爆炸）。

## 四、我们微调用到的全部超参速查

| 超参 | 含义 | 取值/说明 |
|---|---|---|
| `tuner_type=lora` | 只训练低秩增量矩阵（A、B），冻结原权重 | r=16, α=32 → 缩放系数 α/r=2 |
| `target_modules=all-linear` | 对所有线性层挂 LoRA | 含 Q/K/V/O/FFN |
| `quant_method=bnb, bits=4` | 基座权重量化成 4bit（NF4）省显存，量化部分不训练 | 显存 6.5GB 的关键 |
| `lora_dropout=0.05` | 训练时随机丢弃部分 LoRA 通道，防过拟合 | |
| `per_device_batch=1 × grad_accum=8` | 每步实际拼 8 条样本更新一次（等效 batch=8，省显存） | |
| `max_length=8192` | 单条样本截断/填充到的最大 token 数 | 音频特征+回答 |
| `weight_decay=0.1` | 权重衰减，对大参数施加轻微惩罚，正则化防过拟合 | |
| `bf16=true` | 半精度训练（省显存+提速），无精度风险 | 比 fp16 稳（动态范围大） |
| `gradient_checkpointing=true` | 用"算完就丢中间激活、反向时重算"换显存 | 速度略降、显存大降 |
| `logging_steps=5` | 每 5 步打印一次（就是你看到打点的频率） | |
| `eval/save_steps=500` | 每 500 步测评+存档一次 | |

**理解这几个基本就够你盯完任何一次训练了**：step/epoch 看进度，train loss 看"学没学"，eval_loss 看"是不是真学会了"，grad_norm 看"稳不稳"，lr 看"在哪个阶段"，最后用 TrainOutput 看总结算单。
